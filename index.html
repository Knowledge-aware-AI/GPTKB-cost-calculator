Formula and assumptions

The estimator uses a phase-weighted GPTKB 2.0 workload model, not the historical spend in the accompanying workbook. The editable phase table is the source of truth for token consumption. At its defaults and 30 triples/entity, it gives approximately 47.7 API calls, 9.2k input tokens, and 2.1k completion tokens per entity.

  • API calls: 2.9741 expensive-model requests/entity and 2.8235 + 1.3967 × triples other-task requests/entity.
  • Threaded mode: request latency divided by selected concurrent threads, with expensive and other tasks sequenced. ScaDS.AI: each pool is constrained by both completion-token capacity and request latency. Batch: ceil(requests / 50,000) × selected time; the selected round-trip time is interpreted as batch-processing time.
  • Clustering: ceil(entities / 80,000) × chosen minutes, serially added after API work in every execution mode.
  • OpenRouter rate card (USD / 1M input, output): GPT-6 Astra 5/25; GPT-6 Luna 0.05/0.25; Kimi-K3 0.60/2.50; Gemma-27B 0.10/0.30. These are editable planning assumptions in the source, not price quotes. ScaDS.AI reports zero direct API spend and separately shows the OpenRouter-equivalent estimate.
